# Finance

A personal financial command centre. It answers one question — *how am I doing,
and where am I heading?* — from monthly totals and account balances, not
transaction-by-transaction bookkeeping.

## Running it

```bash
python -m venv .venv
.venv\Scripts\activate          # macOS/Linux: source .venv/bin/activate
pip install -r requirements-dev.txt
streamlit run app.py
```

Then open http://localhost:8501. On first run the app is empty — add accounts,
import a spreadsheet, or load the sample dataset to have a look around.

In Docker:

```bash
docker compose up --build
```

## How it is put together

```
app.py                  navigation only
views/                  one screen per file, kept thin
financelib/
  models.py             Account, MonthlyRecord, Goal, Settings, Dataset
  storage/              Repository interface + JSON implementation
  calculations/         net worth, cash flow, performance, goals, projections, tax, insights
  importers/            spreadsheet import
  formatting.py         money, dates, durations
  ui/                   theme, components, charts, page state
tests/                  273 tests, none of which need Streamlit running
tools/make_samples.py   regenerates the synthetic sample data
```

The dependency direction is strictly one way:

```
views  →  calculations  →  models
   ↘         storage    ↗
```

Calculations import models and nothing else. They contain no Streamlit and no
file access, so every financial figure in the app is testable in isolation.

### The data model

One record per month, which mirrors how a finance spreadsheet actually works:

```json
{
  "month": "2026-09",
  "income": 3478.00,
  "spending": 2383.00,
  "spending_categories": { "Housing": 780.00, "Food & groceries": 390.00 },
  "contributions":       { "stocks_isa": 450.00, "cash_isa": 300.00 },
  "balances":            { "stocks_isa": 34487.12, "cash_isa": 18312.40 }
}
```

Balances live on the month, never on the account, so there is exactly one
source of truth for what something was worth. Every field is optional: a month
with only balances still feeds the net-worth chart, and a month with only
income and spending still feeds the savings rate. Blank means *not recorded*,
which is never silently treated as zero.

### Swapping the storage backend

`financelib/storage/base.py` defines the `Repository` interface. `JsonRepository`
implements it against four JSON documents. Moving to SQLite or Postgres means
writing one new class and changing `get_repository()` — no view and no
calculation needs to know.

Set `FINANCE_DATA_DIR` to relocate storage (a mounted volume, an Azure Files
share). JSON writes are atomic and a backup is taken before anything
destructive.

## What it will and will not claim

Numbers are labelled by where they come from:

| Label | Meaning |
|---|---|
| **Recorded** | Exactly what you entered |
| **Calculated** | Derived from your figures |
| **Projected** | Depends on assumptions — not a forecast |

The app refuses to guess. If contributions are missing for any month in a
period, it says growth cannot be separated from what you paid in rather than
quietly attributing the difference to the market. A savings rate with no income
recorded shows as `—`, not `0%`.

## Data safety

Real financial data never enters the repository. `.gitignore` excludes
everything under `data/` except `data/samples/`, which is entirely synthetic and
generated by `tools/make_samples.py`.

The Data and settings page handles export, backup and restore. Backups are
taken automatically before any import, restore, or bulk delete, and restoring a
backup itself takes a backup first — so every destructive action is reversible.

## Tests

```bash
pytest
```

Covers the financial arithmetic plus the edge cases that matter: empty history,
zero and negative income, a brand-new account, missing months, goals with no
target date, projections with no contributions, corrupt data files, and
repeated imports. A separate smoke suite drives the real Streamlit runtime and
asserts every page renders both with a full dataset and with nothing at all.

## Known limitations

- The UK tax year runs 6 April to 5 April, but months are whole. Each April is
  attributed to the tax year it begins, so contributions made 1–5 April land a
  year later than HMRC would count them.
- Investment return is approximated against the starting balance plus half of
  contributions. It is labelled as an approximation wherever it appears.
- Projections apply a constant rate. Real returns are not smooth, and the page
  says so.
